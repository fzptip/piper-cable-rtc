# openpi/docs 文档说明

下面是 `openpi/docs` 目录下三个文档的中文概述，按“它在讲什么”和“你该怎么理解”来整理。

## 1. `docker.md`

### 这份文档在讲什么
它在说明：如何用 Docker 来运行 `openpi` 仓库里的示例和环境。

### 核心意思
- Docker 不是强制必须，但官方推荐使用，因为它能简化安装、提高环境稳定性。
- 如果你的示例依赖 ROS，Docker 还能避免在本机安装一堆 ROS 相关依赖。
- 如果要用 GPU，需要额外安装 NVIDIA Container Toolkit。
- 文档还提醒了两个常见坑：
  - `snap` 安装的 Docker 和 NVIDIA 容器工具不兼容。
  - Docker Desktop 也和 NVIDIA runtime 有兼容性问题。

### 你可以怎么理解
这是一份“运行环境搭建指南”，重点是告诉你：
- 怎么装 Docker
- 怎么让 Docker 支持 GPU
- 怎么用 `docker compose` 启动整个项目或某个具体示例

## 2. `norm_stats.md`

### 这份文档在讲什么
它在解释：模型训练和推理时使用的“归一化统计量”是什么，以及什么时候应该复用已有统计量、什么时候应该重新计算。

### 核心意思
- 模型会对输入的状态和输出动作做归一化处理。
- 这些归一化所需的统计量，是从训练数据里算出来并和 checkpoint 一起保存的。
- 当你拿一个预训练模型去微调新数据集时，有两个选择：
  - 复用原来的统计量
  - 用新数据重新计算统计量
- 如果你的机器人和预训练时的机器人很接近，复用统计量通常更好，因为动作分布会更“像模型熟悉的样子”。
- 文档还列出了不同机器人对应的预训练统计量 ID，以及 `pi0_base` / `pi0_fast_base` 的动作空间定义。

### 你可以怎么理解
这是一份“模型输入输出尺度对齐说明”：
- 它告诉你为什么有些任务需要沿用老的 normalization stats
- 它告诉你不同机器人动作向量每一维代表什么
- 它帮助你在迁移训练时避免“动作定义不一致”导致效果变差

### 实际上最重要的点
- 如果机器人类型和预训练数据集接近，优先试试复用统计量。
- 如果不确定，文档建议两种都试：
  - 复用已有统计量
  - 在新数据上重新计算统计量
- 最后看哪个效果更好再决定。

## 3. `remote_inference.md`

### 这份文档在讲什么
它在说明：如何把 `openpi` 模型部署成远程服务，并从机器人代码里去调用它做推理。

### 核心意思
- 可以把政策模型放到更强的远程 GPU 机器上跑，而不是直接在机器人本机上跑。
- 这样做有两个好处：
  - 推理算力更强
  - 机器人环境和模型环境分离，减少依赖冲突
- 文档先教你怎么启动 policy server。
- 再教你怎么在机器人端安装 `openpi-client`，然后通过 websocket 请求远程服务得到动作。

### 你可以怎么理解
这是一份“远程推理架构说明”：
- 服务端负责加载模型并提供推理接口
- 机器人端负责收集观测、预处理图像、发送请求、接收动作
- 机器人端通常只需要按步调用，不必每一步都重新推理整条动作序列

### 实现时要注意的点
- 图像建议在客户端缩放到固定尺寸，比如 224x224。
- 图像要转成 `uint8`。
- `state` 可以不先手动归一化，服务端会处理。
- 返回的是一个动作 chunk，不是单步动作。

---

## 总结一句话
- `docker.md`：讲怎么把运行环境搭起来。
- `norm_stats.md`：讲模型训练/推理时动作和状态怎么做归一化，以及什么时候复用统计量。
- `remote_inference.md`：讲怎么把模型放到远程服务器上推理，再从机器人端调用。
